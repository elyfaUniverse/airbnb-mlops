# Airbnb MLOps: чтение данных из S3

Учебный проект по работе с данными Inside Airbnb. Ноутбук загружает подготовленный CSV из S3-совместимого хранилища и, при ошибке доступа или сети, может прочитать локальную копию файла.

## Структура проекта

```text
airbnb-mlops/
├── 01_read_data.ipynb  # Чтение данных из S3 и локального файла
├── .gitignore          # Исключения для Git
└── README.md           # Описание и инструкция запуска
```

При работе локально также создаются `.venv/`, `.env` и `data/`. Они не хранятся в Git.

## Источник данных

Данные находятся в Yandex Object Storage:

- endpoint: `https://storage.yandexcloud.net`;
- регион: `ru-central1`;
- bucket: `mlops26-course-bucket`;
- key: `prepared/listings.csv`.

Для чтения объекта необходимы действующие ключи доступа, выданные владельцем хранилища.

## Подготовка окружения

Пример команд для Python 3.12 и Windows PowerShell. Выполняйте их из папки проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install boto3 pandas python-dotenv ipykernel
```

Откройте папку проекта в VS Code. В ноутбуке нажмите **Select Kernel → Python Environments** и выберите окружение `.venv` с интерпретатором `.venv\Scripts\python.exe`.

## Настройка доступа к S3

Создайте в папке проекта файл `.env` и заполните его:

```dotenv
AWS_ACCESS_KEY_ID=ваш_идентификатор_ключа
AWS_SECRET_ACCESS_KEY=ваш_секретный_ключ
AWS_DEFAULT_REGION=ru-central1
S3_ENDPOINT_URL=https://storage.yandexcloud.net
S3_BUCKET=mlops26-course-bucket
S3_KEY=prepared/listings.csv
```

Значения ключей необходимо получить у владельца хранилища. Переменные, заданные в системе до запуска, имеют приоритет над значениями из `.env`.

Файлы `.env`, `secretkeys.py`, папки `data/` и `.venv/` исключены через `.gitignore`. Не добавляйте реальные ключи в ноутбук или репозиторий. Если файл уже отслеживается Git, одного добавления в `.gitignore` недостаточно: его нужно отдельно убрать из индекса.

## Запуск ноутбука

Откройте `01_read_data.ipynb`, выберите ядро окружения проекта и выполните ячейки сверху вниз.

В ноутбуке реализованы две функции:

1. `read_s3_csv(bucket, key)` получает CSV из S3 через `s3.get_object` и возвращает `pandas.DataFrame`.
2. `read_data(bucket, key, local_path=None)` сначала обращается к S3. При ошибке доступа или сети выводит сообщение и читает локальный файл, если путь к нему указан.

Столбец `listing_id` читается как строка. Ошибки разбора CSV не скрываются. Если запасной путь не указан, передаётся исходная ошибка S3; если локальный файл отсутствует, возникает `FileNotFoundError`.

## Проверка результата

После успешного чтения из S3 ноутбук выводит первые строки, размер таблицы и названия столбцов. Если локального файла `data/listings.csv` нет, ноутбук создаёт его из загруженной таблицы. Существующий файл не перезаписывается: необходимо убедиться, что он содержит тот же снимок данных.

Для проверки запасного пути в ноутбуке к ключу S3 добавляется суффикс `.missing`. При отсутствии такого объекта функция сообщает о переходе к локальной копии и возвращает таблицу из `data/listings.csv`.

Если S3 недоступен с самого начала, заранее положите копию того же CSV в `data/listings.csv`. Затем выполните ячейки импортов и определений функций и вызовите `read_data` с локальным путём. Ячейку прямого чтения из S3 в этом случае можно пропустить.
